# 多论文比较准则

## 证据优先级

对同一事实存在多个来源时，按以下优先级使用：

1. `search_compare_paper` 返回且带 `citation_tag` 的目标论文正文。
2. `experiments` 和 `results` 中明确描述的实验事实、数据集、指标与数值。
3. `methods` 中明确描述的模型、算法、训练或推理流程。
4. `research_questions` 中明确列出的研究问题。
5. `innovations`、`limitations`、`future_work` 中作者式总结。
6. `abstract` 和 `keywords` 中的概括性信息。

结构化字段主要用于定位检索主题和补充缺失项，不能覆盖正文证据中的具体事实。结构化字段与正文冲突时明确标记冲突，并以正文证据作为最终报告的事实依据。

## 研究问题比较

比较研究问题时分别判断：

- 目标对象：处理什么数据、任务或系统。
- 优化目标：追求准确性、效率、鲁棒性、安全性、可解释性或其他目标。
- 约束条件：数据量、计算成本、部署环境、威胁模型或评价协议。
- 输出目标：预测、生成、检索、控制、分析或理论解释。

仅共享宽泛领域词不构成强共同点。例如“都研究深度学习”不能单独作为核心共同点。

## 方法比较

将方法拆为四层：

1. 技术范式：监督学习、自监督学习、生成建模、检索增强、强化学习等。
2. 系统结构：主干模型、关键模块、数据流和模块连接。
3. 优化过程：目标函数、训练策略、约束和数据构造。
4. 推理与部署：推理步骤、额外资源、时延和部署依赖。

方法名相同不代表作用相同。必须结合上下文说明同一模块在各论文中承担什么功能。

## 实验与数据集比较

先识别数据集，再判断可比性。一个候选名称只有满足以下至少一项时，才可作为数据集：

- 文本明确称其为 dataset、benchmark、corpus、test set 或中文对应词。
- 与训练集、验证集、测试集、样本数量或数据划分共同出现。
- 在实验设置中作为任务评测载体出现。

GPU、NVIDIA、CUDA、模型名称、优化器、服务器和硬件配置不是数据集。

实验可比性分级：

- **A级，直接可比**：相同任务、数据集、划分、指标和近似协议。
- **B级，部分可比**：任务和指标相同，但数据集、基线或协议不同。
- **C级，不可直接比较**：任务、指标或实验目标不同。
- **U级，信息不足**：抽取信息不足以判断。

只有 A 级可直接比较数值高低。B 级可以比较趋势和覆盖范围，但必须写明条件差异。C/U 级只做并列描述。

## 指标与结果比较

识别指标时保留方向性：

- 越高越好：Accuracy、F1、Recall、BLEU 等，但仅在输入明确时采用。
- 越低越好：Error、Latency、FLOPs、Loss 等，但仅在输入明确时采用。
- 方向未知：只报告数值或定性结论，不判断优劣。

不要跨数据集比较同名指标，不要把相对提升和绝对提升混为一谈，不要把消融实验结果当作主实验排名。

## 创新与局限比较

创新比较回答：

- 相对输入中描述的旧路线，改变了什么。
- 新增能力由哪类实验支持。
- 创新是新模块、新目标、新数据、新协议，还是已有组件的新组合。

局限比较回答：

- 限制发生在数据、方法假设、计算、实验、泛化、安全或部署的哪一层。
- 是作者明确承认，还是从结构化字段中只能观察到证据不足。

后者必须写成“当前抽取信息不足以证明”，不能写成论文固有缺陷。

## 结论强度

使用以下语言控制结论：

- 强证据：多数据集、多基线、消融或鲁棒性验证均有明确结果。
- 中等证据：主实验明确，但覆盖范围有限。
- 弱证据：只有定性描述、单一实验或缺少关键协议。
- 无法判断：结构化输入没有足够实验信息。

报告中的措辞应匹配证据强度：

- 强证据可写“结果支持”。
- 中等证据写“在给定设置下支持”。
- 弱证据写“初步表明”。
- 无法判断写“当前信息不足以判断”。

## 冲突与缺失处理

- 同一论文不同字段冲突时，描述冲突，不自行选择更符合常识的一项。
- 缺少某论文的字段时，不让其他论文的内容补位。
- 某维度只有一篇有信息时，将其写入该论文的特征或取舍，不制造横向差异。
- 所有论文都缺失某维度时，在表格写“未抽取”，正文只需简短说明，不扩写空泛内容。
