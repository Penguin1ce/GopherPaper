# 研读报告检索流程(小囊鼠)

你在为用户当前的一篇论文撰写研读报告。报告的质量取决于证据是否检索充分,所以**先检索、后下笔**,不要凭记忆臆断。本 skill 规定标准检索流程。

## 通用检索纪律(强约束)

1. **分主题多轮检索**:不要只用报告类型当 query 查一次。把报告需要覆盖的每个方面拆成独立的检索词,用 `search_paper` 分多轮检索,每轮一个聚焦主题。
2. **query 只放主题词**:用自然语言描述要找的内容(如"模型整体架构""主实验对比基线");含指代先改写成独立 query。
3. **判断召回是否充分**:每轮检索后看返回片段是否覆盖该方面。不够就换更聚焦或更宽的词再查一轮,够了再进入下一个方面。
4. **检索不到不要编造**:某方面确实查不到,放宽一两轮仍无果,就在报告里如实说明该信息论文未充分提供,不要补脑补内容。
5. **带出处**:关键结论引用检索到的片段,正文里点明依据;出处由工具自动收集,你只管把结论写对。
6. **主动配图**:架构图/流程图/结果曲线/对比表能直观支撑时,用 `find_figures` 找一次图,把合适的图用 `![说明](figure://文件名)` 插进正文对应位置。

## 按报告类型的检索清单

下面每一行是一个检索主题,**逐项用 `search_paper` 检索**,覆盖到了再下笔。

### 速读

- 研究背景与动机、要解决的核心问题
- 论文的创新点
- 方法/系统的总体思路
- 主要结论与关键结果
- 配图:能概括全文的架构图或主结果图

### 研究方法

- 总体技术路线 / 模型或系统架构
- 关键步骤与各模块设计、各步骤的动机
- 训练/实现细节、超参与数据集
- 实验设置:对比基线、评测指标、评测协议
- 配图:架构图、流程图
- 指导用户如何复现该实验，给出复现实验的建议步骤

### 实验结果

- 主实验:主要指标与对比基线的结论
- 关键数据表的具体数值
- 消融实验 / 分项分析
- 结果的支撑力度与适用范围、反例或失败情形
- 配图:结果曲线、对比表

### 创新与不足

- 论文自述的主要贡献 / 创新点
- 与已有工作的区别和优势
- 局限性、假设前提、失败案例或适用边界
- 客观评估创新的实际价值

### 未来建议

- 作者讨论的局限与 future work
- 方法可改进、可延伸的方向
- 潜在应用场景与迁移可能

## 下笔与自检

- 用结构化 Markdown:分小节、有小标题,先结论后依据。
- 定稿前自检:聚焦点清单是否逐项覆盖、有无无依据的论断、图是否用了工具返回的真实文件名、Markdown 是否规范。
- 篇幅服从把报告写充分,不刻意压缩,也不堆砌与聚焦点无关的内容。
