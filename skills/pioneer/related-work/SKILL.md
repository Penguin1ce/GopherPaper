# 相关工作(Related Work)撰写流程(小云雀)

你在为用户的某篇论文写 related work 章节。它和文献综述不同:**篇幅更短、紧扣本文贡献、目的是把前人工作定位好,凸显本文的位置与差异**,而不是面面俱到地梳理整个领域。

## 第一步:锚定本文的贡献

下笔前先和用户确认(已说清的不必重复问):

- 本文要解决什么问题、核心方法/贡献是什么。
- 希望和哪些方向/流派的前人工作对比(related work 要围绕这些组织)。
- 期刊/会议或篇幅要求(决定写多长、铺多宽)。

related work 的每一段最终都要能回答:**这些前人工作和本文是什么关系、本文相对它们做了什么不同。**

## 第二步:按需检索补文献

- 用户已给出要对比的文献就直接用;不全就用 `search_semantic_scholar`(找该方向代表作)+ `search_arxiv`(补最新)+ `search_my_papers`(用户库)补齐。
- 检索 query 聚焦到要对比的子方向,不要泛查。
- 检索结果自带 BibTeX,留作引用,不要编造引用。

## 第三步:按主题分组组织(不要逐篇罗列)

- **按方法流派 / 技术路线分组**,每组一小段或一个主题句,而不是一篇论文一段流水账。
- 每组讲清:这类方法怎么做、有什么共性局限,**然后落到本文的区别**(本文如何改进/规避/不同)。
- 体现**演进关系**(从早期到近期怎么发展)和**对比关系**(不同流派的取舍)。
- 用恰当的对比/转折衔接("Unlike … / 与之不同 …""However …")自然引出本文定位。

## 强约束

- **每个论断挂出处**(作者+年份),引用的文献必须是真实存在/检索返回的,不得虚构。
- **客观定位,不贬低前人**:讲差异和改进,不要写成"前人都很差、只有本文好"。
- **不夸大本文**:本文的优势点到为止,把"为什么不同"讲清楚即可,论证留给实验章节。
- 检索/资料不足以支撑某处对比时,如实说明,不要编造前人工作的细节。

## 收尾

- 用结构化段落(或按子方向加小标题),先讲前人、再落本文位置。
- 末尾可附本章节涉及文献的 BibTeX,便于用户写进 .bib。
- 主动问用户:要不要扩成完整文献综述(可转 literature-review),或润色定稿(可转 academic-polish)。
